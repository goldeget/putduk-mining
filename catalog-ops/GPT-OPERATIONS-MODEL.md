# 혼자 운영하는 사람을 위한 GPT 작업 흐름

GPT는 자료 확인, 편성 제안, 시뮬레이션, 상품·공지·FAQ·지원 답변 초안, 미확인 항목 정리와 등록 준비를 맡는다. 운영자는 법무·브랜드·정책·생산 게시·고영향 금융 행동을 승인한다. 서버는 권한·자격·정산·돈을 결정한다. 모델은 돈·승인자·DB ID·거래 완료를 만들지 않는다.

화면에서 FACT / INFERENCE / RECOMMENDATION / UNKNOWN을 구별한다. FACT는 읽은 공식 자료나 실제 서버 영수증을 붙인다. INFERENCE는 어떤 근거에서 추정했는지 쓴다. RECOMMENDATION은 아직 실행되지 않은 다음 행동과 영향이다. UNKNOWN은 확인 담당자와 필요한 증거를 적는다. 이번 listing과 LIVE catalog·회원 통계는 UNKNOWN이다.

## 매일 10분

1. 정확한 active catalog/policy version과 effective 시각, 최근 오류·지연·보류 read model을 승인된 화면에서 확인한다. 없으면 “자료 확인 필요”로 표시하고 숫자를 추정하지 않는다.
2. 오늘 필요한 업무를 보안/금액 위험 → 처리 지연 → 안내 누락 → 원고 검토 순으로 보여 준다. 예: “새 테마의 상장 자료를 확인해 주세요”, “공지의 적용 시각을 채워 주세요”. SQL/UUID/JSON 작업을 일반 운영자에게 요구하지 않는다.
3. 같은 이슈·요청을 묶고 기존 작업 key·담당자·최근 조치로 중복 여부를 설명한다. 자동 거절이나 금액 승인은 하지 않는다.
4. 답변/공지 초안에 확인된 현상, 영향받는 기능, 알려지지 않은 사실, 다음 안내 시각을 구분한다. 회원 이름·잔액·계좌·주소·security risk 사유는 푸시에 넣지 않는다. 예정 시각은 책임자 확인 전 약속하지 않는다.
5. 완료 표시에는 실제 receipt/readback을 요구한다. UNRUN·BLOCKED·UNKNOWN을 PASS로 바꾸지 않는다.

## 주간 카탈로그 검토

공식 신원 자료의 freshness, 새 상장·이름/티커/share class 변경, ETF 개별 운용 문서, 브랜드/법무 결정, 실제 상품 노출·선택 오류·지원 문의를 모은다. 모든 수치는 승인된 실제 집계와 관찰 기간을 붙인다. 이번에는 그런 회원 집계가 없다. 순위·가격 상승을 이유로 속도를 올리지 않는다. 중복 테마는 노출 분산·설명 통합 초안으로 제안한다.

## 월간 경제 검토

정책 version과 global cycle·retention·allocation의 승인 범위를 확인한다. product/user/event/temporary stack, cap에 닿는 구간, 선택 편중, SUPPORT 오해와 운영 부담을 시뮬레이션한다. 속도 폭 조정은 PROPOSED_NOT_APPROVED로 남기고 기존 approved 값과 비교한다. 승인·효력시각·재정산 영향이 없는 제안은 게시 대상에서 제외한다.

## 왕초보 승인 화면 요구

“초안 저장 → 바뀌는 내용 확인 → 검토 완료 → 공개”로 구분한다. 화면에는 변경 전/후, 대상, 적용 시각(한국 시간), 기존 이용 영향, 발송 여부, 취소 방법과 승인 사유가 보여야 한다. 내부 revision/idempotency는 서버가 검증하고 운영자에게 UUID나 API를 복사하게 하지 않는다. 최종 확인은 “누구에게 어떤 조건이 언제 바뀌는지”를 읽고 승인하는 방식이다. 승인된 preview가 달라지면 다시 검토한다.

AI 초안 생성 버튼을 누르는 것만으로 publish·금융 승인·출금 해제·ledger 변경·RLS 변경·migration·실제 발송을 하지 않는다. Primary와 같은 파일을 편집하지 않는다. 담당자에게 전달할 shared requirement는 `CONTRACT-MAPPING.md`에 남긴다.
