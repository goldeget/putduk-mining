# 퍼뜩 출시일 — 1인 운영 절차

이 문서는 운영 순서와 판단 기준입니다. 오픈 승인이나 실제 서비스 변경 승인이 아닙니다. 출시 책임자가 기능·정책·금전·보안·통합 검사·등록 확인 항목을 완료해야 합니다. 모르는 상태는 정상으로 체크하지 않습니다.

## 출시 전 운영 카드

| 항목 | 출시 전에 실제로 확정할 내용 |
| --- | --- |
| 책임자 | 출시 책임자/출시 책임자 이름과 실제 연락 방법 |
| 사고 연락 | 금전·보안·개인정보 담당과 연결 확인 |
| 공지·지원 | 승인자, 실제 게시 실행 절차/채널, 실제 접수함·운영 시간 |
| 승인 버전 | 승인된 출시 버전 식별자, 적용 정책 버전과 승인 기록 |
| 일정 | 승인된 오픈 시각과 다음 안내 시각(KST) |
| 복귀 | 이전 정상 배포, 호환성 확인 결과와 복귀 담당자 |

현재 이 항목들은 미확정입니다. 한 사람이 운영하더라도 사고 시 부를 담당자는 있어야 합니다. 연락·게시·복귀 방법 중 하나라도 비어 있으면 오픈하지 않습니다. 실제 연락처는 제한된 운영 기록에 보관하고 공개 저장소에 넣지 않습니다.

## 1. 오픈 전 체크

| 순서 | 할 일 | 확인할 실제 결과 | 안 되면 |
| --- | --- | --- | --- |
| 1 | 출시 책임자에게 오늘 버전·오픈 승인 확인 | 정확한 버전 식별자, 기능별 제품 증거, 승인 경제 정책, 승인 기록 | 오픈 중단 |
| 2 | 공식 회원 사이트·운영 화면 로그인 | 브랜드·공식 주소·본인 역할·추가 보안 확인 | 개인정보 입력 중단 |
| 3 | 홈과 제한·안전 모드 열기 | 실제 대기열·제한 상태, 조회 실패 여부 | 빈 값/0건을 정상으로 판단 금지 |
| 4 | 입금·출금·채굴 검증 결과 확인 | 실제 로그인·권한·입출금 검증·원장 대조·자동 작업 증거 | 합성 화면/단위 검사으로 대체 금지 |
| 5 | 고객지원과 공지 경로 확인 | 격리된 검증 환경 등록·처리 결과 재조회·회원 화면 표시·취소·복귀 | 도구 없는 상태로 오픈 금지 |
| 6 | 원고 검토 | 날짜·대상·안내 버튼·조건·미지원 기능·정책/개인정보 검토 | 변수·정책 초안 게시 금지 |
| 7 | 알림 전달 확인 | 실제 앱 안 기록·푸시 권한/선호·중복/조용한 시간 준수 | 임의 이중 발송 금지 |
| 8 | 사고 연락·점검 공지·복귀 확인 | 담당자 응답과 실행 가능한 경로 | 승인 보류 |

기능 상태는 확인 완료 / 실패 / 진행 불가 / 미확인으로 기록합니다. 자동 작업 로그 한 줄을 처리 정상으로 해석하지 않습니다. 일부 회원 검증을 전체 정상으로 확대하지 않습니다.

## 2. 오픈 직후 체크

1. 승인된 환경의 실제 계정으로 로그인·홈·체험·상품·지갑·이벤트·알림·고객지원을 엽니다. 실제 서비스에서 가짜 금융 거래를 만들지 않습니다.
2. 휴대폰과 PC에서 글자·안내 버튼·가려진 버튼을 봅니다. 로그인·보안 확인을 우회하지 않습니다.
3. 운영 화면 홈에서 조회 실패 → 위험/불일치 → 출금 → 본인 확인 → 입금 순으로 봅니다. 승인되지 않은 업무를 실행하지 않습니다.
4. 출시 공지의 제목과 전체 본문을 실제로 읽습니다. 제목만 보이면 전체 안내 완료가 아닙니다.
5. 상담 연결·접수 기록을 확인합니다. 답변 초안은 실제 접수·전송이 아닙니다.
6. 확인 시각·화면·제한·다음 행동을 기록합니다. 캡처의 민감 정보를 가립니다.

## 3. 입금 확인

원화 대기 신청의 신청자·내용·실제 확인한 송금을 대조합니다. 고객 메시지나 캡처만으로 완료를 결정하지 않습니다. USDT는 주소·네트워크·거래 원본과 승인된 반영 기준을 확인합니다. 임의 환율·예시 금액으로 승인하지 않습니다.

유사 요청은 조사 대상이며 자동 중복 판정·반려·지급이 아닙니다. 권한과 실제 확인이 있을 때만 최종 영향을 읽고 사람이 확인한 뒤 기존 명령을 사용합니다. 요청이 바뀌면 다시 확인합니다.

실행 뒤 처리 결과 재조회·지갑 반영·감사를 확인합니다. 응답이 끊기면 같은 송금을 다시 처리하지 말고 기존 요청을 조회합니다. 회원·통화·원본·금액 중 하나라도 맞지 않으면 승인을 멈추고 출시 책임자/금전 담당자에게 연락합니다.

## 4. 출금 확인

1. 현재 상태와 자금 종류를 봅니다. 원금·보상·Bonus·체험을 섞지 않습니다.
2. 본인 확인·역할·추가 보안 확인·받을 곳·네트워크·최종 영향을 읽습니다. AI가 대신 승인하지 않습니다.
3. 보류는 검토 상태입니다. 중복 신청·외부 송금으로 해제하지 않습니다. 공개 가능한 필요한 자료만 공식 채널로 요청합니다.
4. 실제 송금과 영수증을 기존 절차로 확인합니다. 신청·진행·완료를 구분하고 영수증 없이 완료 처리하지 않습니다.
5. 결과가 불분명하면 재송금하지 않습니다. 송금 여부를 먼저 조사합니다. 외부 송금 뒤 임의 보류 해제·잔액 복원은 금지합니다.
6. 금액·수취인 불일치와 중복 송금 의심은 최우선 연락 대상입니다. 알려진 영향만 안내합니다.

## 5. 채굴·자동 작업·서비스 상태 확인

- 실제 회원 채굴 화면과 운영 화면 조회에서 시작·주기·확인 전/확정·제한을 구분합니다.
- 속도와 용량은 다른 조건입니다. 화면 효과·타이머로 금액을 계산하지 않습니다. 적용 정책이 없거나 미확인이면 정상 판정을 보류합니다.
- 출시 책임자가 제공한 실제 관측에서 최근 처리 시각·기준·최근 응답·실패/격리·미처리 구간을 봅니다. 과거 정상 보고를 현재 정상으로 판단하지 않습니다.
- 재시도와 영구 실패/격리를 구분합니다. 버튼 존재는 안전 실행 권한이 아닙니다. 금전 자동 작업은 원본 대조 후 승인된 복구만 사용합니다.
- 정산·원장·지갑·전달 기록·알림을 각각 대조합니다. 전달 실패를 금액 재지급으로 고치지 않습니다.
- 허용 지연·오래된 기록 판단·처리 시간는 출시 책임자가 확정한 실제 기준을 사용합니다. 이 문서는 임의 시간을 정하지 않습니다.

## 6. 장애 연락과 대응

| 현상 | 첫 행동 | 연락·안내 |
| --- | --- | --- |
| 금전 불일치·중복 송금 의심 | 승인/송금/재시도 중단, 원본 보존 | 출시 책임자·금전 담당 최우선 연락. 확인된 영향 범위만 공지 |
| 계정 탈취·정보 노출 의심 | 민감 자료 수집/공유 중단, 증거 보존 | 보안·개인정보 담당 연락. 위험 상세·회원 신원 공개 금지 |
| 조회 실패·자동 작업 지연 | 미확인 기록, 같은 요청 반복 중단 | 실제 처리/거래 영향 조사. 새로고침만으로 정상 판정 금지 |
| 화면·상담·알림 문제 | 실제 안전한 대안 확인 | 서비스 공지/답변. 미검증 메신저·외부 주소로 유도 금지 |

제한·안전 모드의 기능 일시 정지는 역할·현재 상태·사유·영향을 확인한 뒤 승인된 기존 명령만 사용합니다. 이 작업에서 실제 서비스 명령은 실행하지 않습니다. 조회 담당자는 담당자에게 요청합니다. 계정 차단·전체 제한을 임의 확대하지 않습니다.

전달 메모: 시각(KST), 현상, 영향 범위, 기존 요청과 중복 위험, 확인한 사실, 미확인 사항, 이미 한 조치, 필요한 결정, 다음 안내 담당자. 공개 공지와 내부 영수증을 분리하고 인증 정보·내부 원문는 보내지 않습니다.

## 7. 공지·지원 답변

장애 최초/중간/부분 복구/복구/사후/정정 템플릿을 사용합니다. 변수를 실제 확인한 값으로 채우고 원인 추측·전체 잔액 정상·자동 보상·확정 복구 시각을 만들지 않습니다.

원고 준비 → 공개 가능 정보 검토 → 대상·시각·영향 미리보기 → 사람 승인 → 승인된 실행 절차 → 실제 등록 결과/처리 결과 재조회/회원 화면 표시/감사 확인 순서입니다. 게시 실행 절차가 없으면 데이터를 직접 넣는 방법으로 대체하지 않습니다. 자동 발송 여부 확인 전에 수동으로 중복 발송하지 않습니다.

## 8. 서비스 중지·롤백

1. 출시 책임자/책임자가 범위와 사유를 승인하고 진행 중 신청·외부 송금 상태를 보존합니다.
2. 승인된 안전 모드/배포 복귀로 새 요청을 제한합니다. 운영자는 업무 코드·데이터 구조·접근 규칙을 직접 바꾸지 않습니다.
3. 실제 영향과 다음 안내를 공지합니다. 기존 거래가 자동 취소·환급됐다고 말하지 않습니다.
4. 이벤트·공지는 승인된 취소·보관 처리로 예약 발송·노출을 중지합니다. 원장·참가·영수증·감사는 삭제하지 않습니다.
5. 출시 책임자가 이전 버전 호환성, 진행 요청, 돈의 원본·거래·전달 기록, 자동 작업 중복/누락을 대조합니다. 과거 상태로 덮어써 돈의 기록을 없애지 않습니다.
6. 실제 기능 확인·권한·금전 대조·회원 화면 검증 뒤 단계적으로 재개합니다. 앱 재시작만으로 복구를 선언하지 않습니다.
7. 부분/전체 복구를 구분하고 사후 안내·남은 문제·재발 방지를 기록합니다.

## 현재 출시 확인 항목

콘텐츠는 검토용 초안 확인 완료입니다. 실제 게시/알림/상담 계약은 진행 불가, 정책 캠페인은 정책 승인 대기, 보존된 운영 화면의 실제 로그인·권한 검증는 환경 증거를 참조합니다. 출시 책임자 전체 통합 검사·회원 화면 검증·정책·실제 서비스 승인 전 오픈 판정을 하지 않습니다.
