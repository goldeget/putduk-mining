# Cloudflare release gate

Next application success is necessary but does not validate the Cloudflare release runtime. The existing full acceptance workflow now has two independent chains: application -> Next native/Auth acceptance, and cloudflare-build -> workerd native/Auth acceptance. The PR queue-inclusive 20 minute controller is unchanged. Existing Next tests and all security/financial checks remain required.

The Cloudflare build uses the pinned Vite/Vinext/Cloudflare packages and both real Vite build commands. It archives both exact .cloudflare/output/v0 trees, a complete nonempty regular-file SHA256 inventory, reviewed public production build values and a head/manifest/run/attempt-bound receipt. These are deployment inputs; an eventual approved deployment must consume this output without rebuilding. No deployment, Cloudflare token, remote binding proxy or paid infrastructure is used by this gate. Live secrets must be inherited by the eventual authorized deployment, never supplied to this build or artifact.

The installed plugin resolves .dev.vars only for secret bindings. It does NOT override configured text bindings. Therefore workerd acceptance copies each verified output to a task-owned temporary root, replaces only that local copy's worker config with exact test/loopback bindings and adds a local-only probe/delegation module. Every original compiled module and asset must match the deploy output byte for byte. An inverse inventory proves the sole replaced config and sole added module. The clone is named local-preview-only, requires test and exact localhost63421 on every request, is outside uploaded source/output and must never be deployed. The wrapper delegates original.fetch unchanged after isolation validation; it fabricates no session or application response.

Vite preview is invoked programmatically with configFile:false, explicit clone root, Cloudflare plugin only, remoteBindings:false and no inspector/persistent resources. The installed plugin's preview branch reads Build Output from that explicit root, not the repository cloudflare.config.ts. Before any identity seed or browser flow, both actual workerd endpoints must return test/localhost/public-key-hash proof. Both login pages must supply a restrictive CSP and local backend connection target, have nonempty HTML without production backend reference or secret prefix, and all discovered JS/CSS plus member icon/service worker must return nonempty non-HTML bytes. Safe evidence contains hashes, counts and public configuration only.

Each runtime acceptance starts an independent disposable historical201 stack, runs all114 legacy suites before seeding, creates real pre202 identities, retains worker checks, applies202, runs the same29 browser flows and all11 native preservation/concurrency receipts. No assertion roster is reduced, no flaky retry or skipped result is accepted. The final workerd receipt includes runtime/asset/CSP proofs and raw reports. A successful Next chain cannot substitute for the workerd chain.

Release remains conditional on both complete chains for the exact candidate, reviewed artifact identity, native preservation, real Auth and approved host/config/secret preservation. Static checks, a build alone, a probe alone or partial workflow success are not production approval. The first hosted Cloudflare execution may expose adapter/runtime defects; this document does not claim it has passed.
