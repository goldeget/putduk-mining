# 게시 알림의 누락 보완 — 로컬 검증

기존 CMS의 승인된 EVENT/NOTICE 발행 원본은 있었으나 실제 발행 알림을 처리하는 닫힌 소비자가 없었다. 기존 `LIVEOPS_CONTENT_CHANGED.v1`, `complete_outbox_event`, `system_jobs`, `complete_system_job`, 알림 선호 설정과 기기별 전송 큐를 재사용한다. 새로운 공개 RPC, 원장 writer, 경제 정책, 실제 전송은 추가하지 않는다.

발행 원본 처리 시 당시 회원의 ID 집합을 비공개로 동결하고 첫 `LIVEOPS_PUBLICATION_FANOUT_V1` 작업을 같은 트랜잭션에서 등록한다. 작업 payload는 발행 revision/source UUID, 양의 chunk 번호, 이전 회원 UUID cursor만 가진다. 각 작업은 최대 100개 ID를 처리한다. 회원의 현재 상태, 수신 설정, 공지 보관/이벤트 취소 및 최신 발행 revision을 다시 확인한다. 원본 알림, 처리 영수증, 다음 작업과 현재 시도의 성공이 같은 트랜잭션으로 저장된다. 다음 청크는 독립 작업이며 기존 최대 12회 재시도 의미를 바꾸지 않는다.

기존 CMS의 `putduk-mining.liveops-content` 공유 advisory lock으로 발행/보관 명령과 직렬화한다. 작업 원본, cursor 연속성, 처리 수, 다음 작업 연결 및 시도 영수증을 검증한다. 완료 직전 lease도 다시 검사한다. 재시도는 기존 완료 영수증을 검증하고 새 알림을 만들지 않는다. 공개 알림 INSERT에도 지연 원본 검증을 적용해 service 역할의 직접 삽입으로 발행 알림을 위조할 수 없게 한다. 익명/회원의 비공개 함수 실행 권한은 없으며 네 개의 닫힌 SECURITY DEFINER 함수만 추가한다. 기존 63개와 합쳐 정확한 검토 목록은 67개이다.

예약 전과 만료 후의 알림은 기존 회원 소유 정책에 추가된 제한 정책으로 직접 조회와 읽음 처리에서도 숨긴다. 기기 전송에는 기존 동의, 기기 만료/폐기, 조용한 시간, 묶음 수신 설정, 간격과 한도, 발행 원본 취소 검증을 적용한다. HTTP 수락은 기기의 실제 표시 증거가 아니다.

새 native 파일은 격리 DB의 비어 있는 회원 집합에서 101명, 첫 100명과 다음 1명, 늦게 가입한 회원 제외, 다음 작업 삽입 실패의 전체 rollback, 완료 replay, 예약/만료 직접 RLS, 기기 동의/quiet hours/만료 및 청크 사이 보관 처리와 위조 INSERT를 검증한다. 기존 fixture를 삭제해 조건을 만들지 않는다. 전체 fresh reset 후 실행 결과가 기능 수용의 근거이다. Worker 단위 검증은 명령 전달과 실패 보존의 근거이며 실제 DB 알림 성공을 대신하지 않는다.

초기 ID 집합의 INSERT SELECT 비용 및 대규모 성능, 실제 외부 Web Push 발송/기기 표시, 운영 사용 및 PRODUCT COMPLETE는 아직 검증되지 않았다. 원문 전체 SQL의 정확한 복원이라고 주장하지 않는다. 이는 확인된 원본 계약과 기존 구현을 재사용한 누락 보완이다. 원격 서비스, 유료 AI, 실자금 및 배포는 변경하지 않는다.
