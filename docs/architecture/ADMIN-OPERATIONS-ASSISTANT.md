# 관리자 공통 명령과 운영 도우미

상태: **V1 필수 계약 / 구현 미완료**. 2026-10-03 운영자 중심 요구를 반영한다. 이 문서는 동작·제품 완료 증거가 아니다. 기존 금전 명령을 바꾸거나 경제 숫자·자산·외부 운영 환경을 승인하지 않는다.

## 운영 화면

운영자는 값 입력, 대상 선택, 적용 시점, 변경 미리보기와 확인으로 작업한다. 별도 고급 모드나 JSON·SQL·환경변수·Rule ID·버전 키 입력을 두지 않는다. 필요한 정책 한도는 쉬운 이름의 필드로 제공하며 내부 버전·감사·outbox는 서버가 관리한다. AI 제공자가 없어도 모든 정상 운영을 완료할 수 있어야 한다.

운영 도우미는 관리자 안의 필수 구성이다. 실제 권한으로 조회한 대기 건수·금액·최장 대기·조회 시각과 연결 화면을 보여주고, 설명과 편집 가능한 초안을 준비한다. 확인되지 않은 값은 추정하지 않는다. 공급자 장애 때도 승인된 조회와 양식 기반 초안 기능을 유지한다.

## 하나의 실행 경계

```text
일반 관리자 양식 ───────────────┐
                              ├─ 운영자의 명시 확인
운영 도우미 → 검토·편집 가능한 초안 ┘
→ 동일 서버 권한·세션·origin·검증·필요한 작업 확인
→ 기존 승인된 도메인 명령
→ 실제 영수증·감사·outbox·사용자 안내
```

도우미에 별도 지급 코드, 자동 실행 endpoint, 서비스 키나 금전 RPC 접근을 주지 않는다. AI가 초안을 만들었다는 사실은 실행 권한이 아니다. 최종 확인과 TOTP는 운영자만 수행하며 도우미가 토큰을 읽거나 생성·소비하지 않는다.

현재 재사용할 서버 경계는 `apps/admin/app/(control)/_lib/command-gate.ts`, `apps/admin/lib/auth/command-families.ts`, 기존 입출금 route/action과 `docs/architecture/WS-04-DOMAIN-COMMAND-CONTRACT.md`다. 이 계약의 public RPC 이름에 별칭을 추가하지 않는다. 상품·행사·공지 등 미구현 명령의 이름이나 테이블을 도우미 때문에 임의로 만들지 않는다. 해당 도메인 계약과 실제 서버 구현을 먼저 정리해야 한다.

## 새 관리자 기능의 필수 묶음

각 기능은 한 등록 항목으로 다음을 함께 정의한다.

| 항목 | 서버의 책임 |
| --- | --- |
| 입력 | 필드 타입·단위·범위·사유·허용 대상과 시간 |
| 권한 | 현재 역할·세션·AAL2·기능 권한·필요한 작업 확인 |
| 조회·미리보기 | 허용된 최소 데이터, 조회 시각과 현재 상태, 예상 대상·금액·예산 |
| 초안 | 편집 가능한 실제 양식으로 매핑; 미결 값과 없는 기능을 표시 |
| 확인 | 최종 양식의 현재 값과 대상을 운영자가 확인; AI 자동 실행 금지 |
| 실행 | 일반 UI와 동일한 서버 검증 및 도메인 명령·요청 키 |
| 결과 | 실제 영수증과 불확정 응답 구분, 안전한 같은 요청 재시도, 감사·후속 이벤트 |

등록 존재는 구현 완료가 아니다. 지원하지 않는 기능을 실행 버튼·성공 상태로 제시하지 않는다. 초안의 대상·금액·기간을 바꾸면 이전 미리보기와 확인을 무효화한다. 재시도는 같은 논리 요청의 키를 유지하며 금액·사유가 달라지면 새 검토를 요구한다.

## 경제·지급·정책

실제 입금, 운영 보너스, START 전환, 추천·행사 보상은 원금 분류와 자격·예산·회계를 공유한다고 추정하지 않는다. 승인된 도메인 계약으로 각각 구분한다. 미결 수익률·등급 혜택·특별 캠페인 한도는 도우미가 선택하거나 기본값으로 활성화하지 않는다.

상품은 승인된 버전 catalog를 사용하며 채굴과 정산은 서버 규칙을 따른다. AI가 행사 초안을 만들더라도 결정적 코드와 운영자 승인만 게시·기간·대상·예산·지급을 결정한다. 이벤트 종료는 해당 버전의 적용 종료이며 다른 활성 정책을 덮어써 과거 배율로 되돌리는 방식은 금지한다.

금전 실행 결과는 실제 DB 영수증이 일치해야 성공이다. 응답 끊김, 미확인 조회, 금액 불일치, 누락 원장이나 outbox는 성공으로 표현하지 않는다. 도우미는 송금·적립 완료를 모델 문장으로 주장할 수 없다.

## 데이터와 모델 경계

운영 도우미 요청은 회원 AI와 별도 관리자 세션·현재 역할을 다시 확인한다. 클라이언트의 actor·역할·대상 목록·조회 수치를 신뢰하지 않는다. 허용된 이름 있는 조회만 실행하며 임의 SQL·테이블 이름·필터 코드를 입력받지 않는다. 서비스 클라이언트는 서버에만 존재한다.

대기열·회원·금액·거래·KYC·위험 정보·주소·계좌·세션·토큰·비공개 규칙은 외부 모델이나 공용 AI 캐시에 보내지 않는다. 조회 숫자와 영수증은 결정적으로 조합해 표시한다. 제공자는 승인된 공개 문구와 비식별 초안 구조에만 제한해 사용하며 실제 모델 호출 없이 모델 결과를 흉내 내지 않는다. 외부 모델 활성화는 별도 비용·개인정보·품질 gate를 따른다.

운영 초안이 지속 저장될 때는 별도의 승인된 관리자 소유권·보존·삭제·감사 계약이 필요하다. 현재 회원 AI의 세션 메모리나 저장 상태를 그대로 운영 승인 기록으로 재사용하지 않는다. 원문 질문과 모델 내부 추론을 감사 로그에 무제한 저장하지 않는다.

## Scene과 연출 연결

상품·행사·배율 초안은 실제 catalog·서버 정책과 연결된 미리보기만 제공한다. Scene과 애니메이션은 서버의 현재 채굴·중지·정산 상태를 표현하며 시각 타이머나 효과가 보상을 만들지 않는다. 운영자용 Scene 선택은 승인된 장면 이름과 미리보기로 제공하고 asset ID·manifest 버전·렌더링 옵션을 직접 입력시키지 않는다.

canonical Visual Lab, 시각·자산·테마·모션 문서를 따른다. 여섯 중립 rank, 반응형 화면, 키보드·명암·축소 모션·연결 복구와 성능 gate가 적용된다. 미승인 master는 운영 도우미가 게시하거나 V1 rank 혜택으로 해석하지 않는다.

## 완료 증거

현재는 계약과 기존 실행 경계가 있다. 운영 도우미의 실제 화면·조회·초안·공통 등록·권한 회귀·제품 증거를 구현하기 전까지 V1 완료로 세지 않는다.

2026-10-03 소스 조사에서 `setSafeModeAction`의 상태 upsert와 감사 insert가 별도 요청임을 확인했다. 해당 기능은 원자적 명령·안전한 재시도와 입력 검증 후 작업 확인 소비가 보완되기 전까지 도우미의 실행 준비 완료 항목으로 등록하지 않는다. API와 `requireHighImpactPrincipal`은 `hasAdminCommandOrigin`으로 설정된 관리자 origin을 동일하게 비교한다. 누락·다른 origin은 identity·운영 세션·작업 확인 소비 전에 거절하며 Host/전달 Host를 신뢰해 우회하지 않는다. 현재 역할·AAL2·운영 세션·일회용 명령별 확인은 그대로 유지한다. 전체 후보 CI에서 실제 양식 동작도 확인해야 한다. 실제 채굴의 `calculateSettlement`는 현재 단위 검사에서만 호출되며 기존 `record_mining_settlement`와 승인된 규칙을 사용한 서버 실행 연결은 별도 검증 대상이다. 이 관찰을 공통 명령 구현 완료로 확대하지 않는다.

필수 검사는 역할·세션·TOTP·origin 거절, 모델/입력 주입, 교차 회원·운영자 데이터 누출, 초안 변조와 오래된 상태, 예산·정책 변경, 중복 실행·동시 승인·응답 끊김, 공급자 비활성/장애, 실제 서버 영수증과 접근성·모바일/태블릿/데스크톱·테마·축소 모션·렌더 화면·Visual Lab 비교다. 화면이나 테스트 fixture 존재만으로 PRODUCT COMPLETE를 선언하지 않는다.
