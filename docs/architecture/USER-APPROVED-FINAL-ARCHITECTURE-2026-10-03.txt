# PUTDUK MINING — ULTIMATE FINAL ARCHITECTURE

## 0. 최종 제품 정의

PUTDUK MINING은 다음 다섯 시스템이 하나로 결합된 플랫폼으로 완성한다.

1. **Funding-Based Mining Economy**
2. **GPT/Claude-style Mining Capacity System**
3. **Operator-Controlled Admin Platform**
4. **PUTDUK Native AI System**
5. **Search / AI Discovery / SEO / GEO Platform**

사용자는:

`실제 원금 입금`
→ `채굴 원금 증가`
→ `Tier 자동 상승`
→ `Mining Capacity 증가`
→ `Mining Speed 증가`
→ `Scene 강화`
→ `실제 서버 채굴`
→ `PENDING`
→ `Settlement`
→ `VERIFIED`

를 경험한다.

운영자는 프로그래밍 지식 없이:

`선택 → 입력 → 미리보기 → 적용`

만으로 플랫폼 전체를 제어한다.

AI는 관리자와 사용자가 이 모든 기능을 자연어로 더 쉽게 이용하도록 돕지만, 돈·권한·보안 규칙을 우회하지 않는다.

OpenAI 공식 지침상 공개 사이트는 ChatGPT Search에 표시될 수 있으며, 요약·snippet·citation을 위해 **OAI-SearchBot을 차단하지 않는 것이 중요**하다. GPTBot은 학습 제어용이며 ChatGPT Search 노출 제어와 역할이 다르다.

따라서 production public site의 robots 정책:

`OAI-SearchBot`
→ public content Allow.

GPTBot:
→ PUTDUK의 별도 training policy에 따라 allow/disallow를 결정.

**Search visibility를 위해 GPTBot까지 허용할 필요는 없다.**

# 44. OpenAI crawler + Cloudflare

Cloudflare/WAF가 OAI-SearchBot을 403으로 막지 않는지 배포 검증에 포함한다.

OpenAI도 WAF/CDN/bot mitigation이 crawler를 잘못 막을 수 있다고 명시한다.

단 crawler 허용을 이유로 Admin/API 보호를 약화하지 않는다.

Public content만 허용.

# 46. Google / Gemini / AI Overview

Google은 AI Overview와 AI Mode에 **별도 AI SEO 파일이나 특별 schema가 필요하지 않으며 기존 SEO 기반이 그대로 적용**된다고 공식적으로 명시한다. 페이지가 Google Search에 index 가능해야 하며 중요한 내용은 텍스트로 제공하고, 내부링크·페이지 경험·정확한 구조화 데이터를 유지해야 한다.

따라서 `llms.txt` 같은 비표준 파일을 핵심 ranking mechanism으로 간주하지 않는다.

원한다면 보조 파일로 제공할 수 있지만 **Google AI 노출의 필수 조건으로 사용하지 않는다.**

자동화.
